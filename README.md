# pi-factory-trim

A pi extension that reduces outgoing conversation size when the active model's
`provider/id` matches `factory|magpie`. It re-encodes older inline images at a
lower resolution (and drops them with `[image removed to fit request size]` only
if compression fails or the request is still over budget), and shortens large
tool result text while preserving the beginning and end. Changes are
request-local: saved sessions, assistant messages, tool call/result pairing, and
user text remain intact.

## Why

When pi talks to Claude models through [magpie](https://github.com/yetone/magpie)'s Factory provider, long sessions or sessions with pasted images can fail with
`413 Factory: Request Entity Too Large`. pi resends the whole conversation each turn with base64 images inlined, so the body eventually exceeds Factory's (undisclosed) byte limit. See [yetone/magpie#2082](https://github.com/yetone/magpie/issues/2082). Factory's own Droid CLI handles this by dropping older images/PDFs from large requests (changelog v0.239.0).

This extension trims **before** sending, on pi's `context` hook, so the request stays under budget instead of failing and retrying.

## Install

```sh
git clone https://github.com/psylch/pi-factory-trim
cd pi-factory-trim && npm install
```


From this directory, run `npm install`, then:

```sh
pi install /absolute/path/to/pi-factory-trim
```

Alternatively, copy `index.ts`, `src/`, and `package.json` into
`~/.pi/agent/extensions/pi-factory-trim/` and restart pi.
For a single invocation: `pi --extension /absolute/path/to/pi-factory-trim/index.ts`.


## Configuration

Set environment variables before starting pi:

| Variable | Default | Meaning |
| --- | --- | --- |
| `PI_FACTORY_TRIM_COMPRESS` | unset | Set exactly `0` to turn off image compression and use the drop-only behaviour. |
| `PI_FACTORY_TRIM_KEEP_FULL` | `2` | The last N inline images are sent unchanged. |
| `PI_FACTORY_TRIM_TIER1_COUNT` | `3` | The next N older images are re-encoded at up to 1568px (JPEG quality 75); all older ones at up to 768px (quality 60). |
| `PI_FACTORY_TRIM_KEEP_IMAGES` | `3` | Drop-only mode (`PI_FACTORY_TRIM_COMPRESS=0`, or if compression cannot start): keep the last N inline images and replace older ones. Budget pressure can remove these too. |
| `PI_FACTORY_TRIM_MAX_TOOL_CHARS` | `30000` | Initial per-block tool text limit. Keep 40% head and 40% tail plus a truncation marker. |
| `PI_FACTORY_TRIM_BUDGET_BYTES` | `3500000` | Target UTF-8 bytes of `JSON.stringify(messages)`. |
| `PI_FACTORY_TRIM_MATCH` | `factory\|magpie` | Case-sensitive JavaScript regex against `provider/id`; `.*` enables every model. |
| `PI_FACTORY_TRIM_DISABLE` | unset | Set exactly `1` to disable. |

Numeric values must be nonnegative safe integers; invalid or empty values use
defaults. An invalid regex causes the context hook to return without changes.
Configuration is read on each context event. Interactive clients receive a short
notification when anything changes, for example
`Factory trim: compressed X, removed Y, truncated Z; <before> → <after> bytes`
(before is the original request estimate);
headless use works without UI.

### Image compression

Images in user and tool result messages are counted newest first. The newest
`PI_FACTORY_TRIM_KEEP_FULL` stay byte-identical; older ones are re-encoded with
pi's own `resizeImage` (Photon/WASM, in a worker thread). pi's resizer returns
its PNG candidate whenever that fits the byte limit, so the extension calls it
with the original size as the limit and, if the result is a PNG, once more with
the PNG size as the limit so the JPEG at the tier's quality can win. A result is
used only if it is smaller than the original and keeps the tier's full
dimensions; otherwise the original image is sent. If the resizer fails or returns
nothing, the image is replaced by the placeholder (counted as removed).

Results are cached in memory by SHA-256 of the image data plus tier (up to 200
entries, least recently used evicted), so later turns don't re-encode. An image
re-encodes once more when it ages from tier 1 into tier 2. The first encode
costs roughly 1–2.5 s per large screenshot (see below); up to 4 run in parallel.

Compressed images are never dropped by count. Afterwards the normal budget loop
runs: if the request is still above `PI_FACTORY_TRIM_BUDGET_BYTES`, it removes
the oldest remaining images (compressed or not), then shortens tool text. An
image compressed and then removed by the budget loop is counted in both numbers.
If compression throws for any reason, the extension falls back to drop-only trim.

Measured with `npm run measure` on the fixtures in `test/fixtures/` (deterministic
screenshot-like PNGs generated by `npm run fixtures`, Python + Pillow), Linux,
Node 20, @earendil-works/pi-coding-agent 1.2.0:

| Fixture | Original (base64 bytes) | Tier | Result | Base64 bytes | Of original | Time |
| --- | ---: | --- | --- | ---: | ---: | ---: |
| screenshot-1920x1080.png | 483664 | 1 (≤1568px, q75) | image/jpeg 1568x882 | 240840 | 49.8% | 910 ms |
| screenshot-1920x1080.png | 483664 | 2 (≤768px, q60) | image/jpeg 768x432 | 52940 | 10.9% | 901 ms |
| screenshot-2880x1800.png | 1336124 | 1 (≤1568px, q75) | image/jpeg 1568x980 | 265064 | 19.8% | 2396 ms |
| screenshot-2880x1800.png | 1336124 | 2 (≤768px, q60) | image/jpeg 768x480 | 57356 | 4.3% | 1347 ms |

Real screenshots compress differently; photos and already-compressed JPEGs shrink less.

### Budget loop

After initial trimming, the budget loop removes remaining images oldest first,
then reduces the largest remaining tool text blocks using a 2000-character limit
(800 characters at either end plus the marker); ties choose the older block.
Stats count distinct shortened text blocks. If protected content still exceeds
the budget, trimming stops when no eligible content remains.

## Limitations

The 3.5MB budget is a guess: Factory's actual limit is undisclosed. Base64 image
size usually dominates. This handles pi's inline image blocks; it cannot identify
PDFs or attachments embedded in arbitrary text or other message types. Magpie may
translate or re-serialize requests, so actual wire size differs from this estimate;
system prompts, tool definitions, and transport overhead are not included.  Removing images and shortening tool
output can lose useful context; it cannot guarantee that every request fits.
Downscaled older images lose fine detail (small text may become hard to read at
768px), and JPEG drops transparency. Compression has been tested with the real
resizer outside pi, not yet against Factory itself.

## Test result

Manual test on macOS, pi v1.1.0, model `factory/claude-opus-5-5` via magpie, with a session containing several large images:
with the extension the request succeeded (7 older images replaced by placeholders, 1 kept); without it the same request did not complete (timed out). One machine, one scenario: not a guarantee.

Note: magpie's Factory plugin `@magpie-community/opencode-factory-auth` 0.1.26 now retries once on 413 with older images replaced. This extension is complementary: it trims proactively before the first request and also shortens oversized tool output.

## 中文说明

此 pi 扩展在模型的 `provider/id` 匹配 `factory|magpie` 时，压缩较旧的内联图片，
并保留工具输出的头尾以缩小请求。只修改本次请求，不修改已保存的会话、助手消息或用户文字。
可通过 `pi install /绝对路径/pi-factory-trim` 安装。环境变量见上表；
`PI_FACTORY_TRIM_MATCH='.*'` 对所有模型启用，`PI_FACTORY_TRIM_DISABLE=1` 禁用。

图片压缩：最近 `PI_FACTORY_TRIM_KEEP_FULL`（默认 2）张图片原样发送；之后的
`PI_FACTORY_TRIM_TIER1_COUNT`（默认 3）张用 pi 自带的 `resizeImage` 缩到 1568px、JPEG 质量 75；
更旧的缩到 768px、质量 60。只有结果更小时才替换，结果按 SHA-256 缓存。压缩失败的图片替换为占位文字。
若请求仍超过预算，再从最旧的图片开始删除。`PI_FACTORY_TRIM_COMPRESS=0` 恢复只删除不压缩的旧行为。
示例截图压缩后约为原来的 4%–50%（见上表）。
默认 350 万字节只是估计，magpie 转换后的实际请求大小可能不同。
